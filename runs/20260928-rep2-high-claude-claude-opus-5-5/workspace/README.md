# Overhead — custom star-map tees

Customers pick a place + moment; the site computes the real sky overhead (stars, constellations,
Moon phase, planets) and prints it DTG on a Bella+Canvas 3001 via Prodigi. Payment via Stripe Checkout.

## Flow
1. `/design` — client-side studio. The artwork is generated by `src/lib/chart.ts` (pure SVG), so the preview
   is exactly what gets printed.
2. `POST /api/checkout` validates the design and creates a Stripe Checkout Session. The design is stored
   (compact-encoded, chunked) in session metadata; no database.
3. Stripe `checkout.session.completed` / `checkout.session.async_payment_succeeded` → `POST /api/webhooks/stripe`
   → `fulfillCheckoutSession()` re-fetches the session, requires `payment_status === "paid"`, then creates the
   Prodigi order with `idempotencyKey = session.id` and writes `prodigi_order_id` back to session metadata.
   The `/order/[id]` page calls the same idempotent function as a fallback if the webhook is late.
4. Prodigi downloads the print file from `/api/print/<design>.<hmac>.png` — a 4680×5790 transparent PNG rendered
   on demand with resvg (HMAC-signed so nobody can use the endpoint as a free renderer).

## Env vars
| Name | Purpose |
| --- | --- |
| `STRIPE_SECRET_KEY` | Stripe secret (or restricted) key |
| `STRIPE_WEBHOOK_SECRET` | Signing secret of the webhook endpoint pointing at `/api/webhooks/stripe` |
| `PRODIGI_API_KEY` | Prodigi API key |
| `PRODIGI_API_URL` | Defaults to sandbox `https://api.sandbox.prodigi.com/v4.0`; set `https://api.prodigi.com/v4.0` for live |
| `ORDER_SIGNING_SECRET` | Random secret for artwork URL HMACs — never rotate without a migration plan (open orders reference it) |
| `SITE_URL` | Public origin Prodigi fetches artwork from (must not be behind Vercel Deployment Protection) |

## Data
`src/data/sky.json` is built by `npm run data` from the d3-celestial catalogue (BSD-3, see `src/data/LICENSE-d3-celestial.txt`).
