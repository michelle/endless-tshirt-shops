# RESONA — one-of-one generative t-shirt store

RESONA turns a customer's **name** into a unique, deterministic piece of generative art
and prints it on a Bella + Canvas 3001 t-shirt with direct-to-garment (DTG) technology.
Every shirt is a one-of-one: change a single letter and the whole composition changes.

```
Customer types a name
        │
        ▼
 /api/checkout ──► Stripe Checkout (hosted)   ← card details never touch this app
        │                    │
        │                    ▼ payment succeeds
        │            /success?session_id=…  (server verifies payment_status === "paid")
        │                    │
        │                    ▼
        │            Prodigi POST /v4.0/orders
        │            asset URL = /api/design?t=<signed params>
        ▼
 /api/design  → SVG → PNG (resvg)  ← Prodigi downloads the print-ready 4677×5787 @300dpi file
```

## Why this concept

DTG has no colour limits and no minimum order, so the store is built around something
only DTG can do well: **a fully custom, full-colour, one-at-a-time design**. The artwork
is generated by a deterministic engine (`lib/design-svg.ts`) seeded from the name, so it
is genuinely original yet reproducible — the same name always prints the same file.

## Stack

| Concern | Choice |
| --- | --- |
| App | Next.js 14 (App Router) + TypeScript |
| Payments | Stripe Checkout (hosted) |
| Fulfilment | Prodigi Print API v4 (sandbox by default) |
| Design engine | Deterministic SVG generator + `opentype.js` text→outline |
| Rasteriser | `@resvg/resvg-wasm` (platform-independent WASM) |
| Hosting | Vercel |

## Environment variables

| Name | Required | Notes |
| --- | --- | --- |
| `STRIPE_SECRET_KEY` | yes | Stripe secret key (`sk_test_…` / `sk_live_…`) |
| `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` | no | Only needed if you add Stripe.js client code |
| `PRODIGI_API_KEY` | yes | Prodigi API key |
| `PRODIGI_API_BASE` | no | Defaults to `https://api.sandbox.prodigi.com/v4.0` |
| `DESIGN_SECRET` | yes (prod) | HMAC secret that signs design URLs |
| `STRIPE_WEBHOOK_SECRET` | no | Enables signature-verified webhooks |

The app derives its own public origin from request headers, so it works on any
deployment URL without extra configuration.

## How to test the deployed store

1. Open the deployment URL.
2. Type a name, pick a palette / style / shirt / size.
3. Click **Create & buy**.
4. Pay with the Stripe test card:
   - Card `4242 4242 4242 4242`
   - Any future expiry, any CVC, any postal code
5. You are redirected to the confirmation page, which shows the **Prodigi order ID**.
6. Verify the order in the Prodigi sandbox dashboard or via the API:
   `GET https://api.sandbox.prodigi.com/v4.0/orders/{id}`.

Reloading the confirmation page does **not** create a duplicate order — Prodigi
de-duplicates on `idempotencyKey = stripe-<session id>`.

## Known gaps / limitations

- **Temporary deployment:** the Vercel temporary deployment expires (~60 min) and is
  claimable. Claim it or deploy under your own Vercel account for a durable URL.
- **Prodigi sandbox does not print or ship** and does not charge. Orders created there
  will sit at `InProgress`.
- **The print file is rendered on demand.** The first request for a given design takes
  ~8–16 s; the response is then cached immutably. The browser pre-warms the render during
  checkout and the confirmation page warms it before contacting Prodigi, so Prodigi's
  download is served from cache. If a design URL is ever requested cold by Prodigi, it
  still succeeds (the function limit is generous) but is slower.
- **Print export resolution is 3600 px wide (~231 dpi)** for serverless speed; Prodigi
  scales it to the print area. Raise `PRINT_EXPORT_WIDTH` in `lib/theme.ts` to 4677 for
  the full 300 dpi file at the cost of slower renders.
- **Asset URL depends on the deployment host.** If the hostname changes (e.g. the
  temporary deployment expires), already-created Prodigi orders that have not yet
  downloaded their artwork will fail to fetch it. Use a stable custom domain in
  production.
- **Fulfilment is triggered from the success page.** A webhook route exists
  (`/api/webhook`) for robustness; set `STRIPE_WEBHOOK_SECRET` and register the endpoint
  in production so orders are still sent if the customer closes the browser before the
  redirect.
- **No order database.** Order state lives in Stripe + Prodigi. Production should add a
  datastore for support, refunds and reporting.
- **No auth/admin UI, no tax/shipping-rate logic, no email beyond Stripe's receipt.**
- **Design preview uses web fonts; the print file uses embedded outlines** — they match,
  but if Google Fonts is blocked the on-screen preview falls back to system fonts.

## Production checklist

1. Replace the Stripe **sandbox/restricted** key with a live secret key on a claimed
   account; complete Stripe onboarding.
2. Swap `PRODIGI_API_BASE` to `https://api.prodigi.com/v4.0` and use a **live** Prodigi
   key. Place a sample order first.
3. Set a strong `DESIGN_SECRET` and a stable custom domain (so asset URLs never move).
4. Register the Stripe webhook (`checkout.session.completed`) and set
   `STRIPE_WEBHOOK_SECRET`.
5. Add a database + admin view; add shipping/tax rules and an order-confirmation email.
6. Review pricing: Prodigi costs ≈ **$11.89 + $4.62 shipping** to the US for this SKU;
   the store charges **$38** with free shipping.
7. Verify Prodigi's print-area dimensions for the exact SKU/colour you sell and re-check
   `PRINT_WIDTH` / `PRINT_HEIGHT` in `lib/theme.ts`.
