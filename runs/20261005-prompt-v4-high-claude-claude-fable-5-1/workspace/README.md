# Dayprint

**The weather of one day in your life, printed on a shirt.**

A customer picks a place and a date (any day since 1940). We fetch that day's real hourly
weather from the ERA5 reanalysis archive (via Open-Meteo), render it as a 24-hour radial
"day print" — sky colour per hour, temperature as wedge length, rain/snow ticks, sunrise and
sunset, the moon's actual phase — and print it direct-to-garment on a Bella + Canvas 3001 tee
through Prodigi. Every shirt is generated from the customer's own data; no two are alike.

```
public/               storefront (static) — index.html, app.js, success.html
public/lib/dayprint.js  the renderer: DayData -> SVG. Shared by browser (preview) and server (print file)
api/                  Vercel serverless functions
  config.js           public config (prices, shirts, date window)
  geocode.js          place search (Open-Meteo geocoding proxy)
  day.js              hourly weather for a place+date (normalised DayData)
  art.js              signed, print-ready PNG (4680x5790, transparent) — what Prodigi downloads
  checkout.js         creates a Stripe Checkout Session; design stored in metadata
  stripe-webhook.js   checkout.session.completed -> Prodigi order (idempotent)
  order-status.js     success-page status + fulfilment fallback
lib/                  weather fetcher, spec signing, Stripe/Prodigi clients, fulfilment, rasteriser, fonts
scripts/deploy.mjs    deploy to Vercel + register Stripe webhook + redeploy with secret
scripts/e2e.mjs       headless end-to-end purchase with Stripe's test card
scripts/dev-server.mjs local stand-in for Vercel
tests/                node:test unit tests (npm test)
```

## Order flow

1. Browser renders a live preview with `renderSVG()` from the same module the server uses.
2. `POST /api/checkout` validates the design, confirms weather exists for that day, and creates a
   Stripe Checkout Session. The design is flattened into session + PaymentIntent metadata; the
   product image is a signed artwork URL.
3. Customer pays on Stripe's hosted page (address + phone collected there).
4. Stripe calls `/api/stripe-webhook`. After signature verification, `lib/fulfill.js` creates the
   Prodigi order with `idempotencyKey = session.id` and records `prodigi_order_id` on the
   PaymentIntent. Nothing is sent to Prodigi before `payment_status === 'paid'`.
5. The success page polls `/api/order-status`, which also performs fulfilment if the webhook has not
   arrived yet (same idempotent path), and shows the Prodigi order id and print status.
6. Prodigi downloads the artwork from `/art/<spec>/<hmac>.png` — a deterministic, HMAC-signed URL,
   so no file storage is needed and the link cannot be forged.

## Run locally

```sh
cp .env.example .env     # fill in keys
npm install
npm run dev              # http://localhost:3000 (PORT=3456 npm run dev to change)
npm test
npm run render:test      # writes sample print files to ./out
```

## Deploy

```sh
npm run deploy             # anonymous Vercel deployment + Stripe webhook wiring (no login needed)
npm run deploy -- --fresh  # new anonymous URL (use when the previous one expired)
npm run deploy -- --prod   # production deploy on a logged-in, linked Vercel project
```

Anonymous ("temporary") Vercel deployments expire 60 minutes after creation unless claimed via
the claim URL the CLI prints. Once claimed they live in your Vercel account like any project.
The deploy script passes all runtime env vars with `-e`; after claiming, set them in the Vercel
project settings instead.

Environment variables: see `.env.example`. `lib/assets.js` (resvg WASM + fonts as base64) is
generated by `npm run build:assets`; regenerate it if you change fonts.

## Print specs

- SKU `GLOBAL-TEE-BC-3001`, front print area 4680 x 5790 px (15.6" x 19.3" at 300 DPI), `sizing: fitPrintArea`.
- Artwork is RGBA PNG with a transparent background; every ink colour is fully opaque and pre-blended
  against the garment colour (no translucent gradients, which print muddy on DTG).
- Design is ~11.7" wide, starts ~2" below the collar; thinnest line 6 px (0.5 mm); smallest text 46 px (~11 pt).
- Fonts: DM Serif Display, IBM Plex Mono (SIL OFL), bundled in `lib/fonts`.
